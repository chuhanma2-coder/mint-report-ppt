# rc.5 修复与验收记录（2026-09-06）

## 结论

本轮按新的授权推送 GitHub **候选代码**，不替换本机已安装 rc.4，不创建 0.4.0 正式版。不能声称“所有剩余问题已彻底解决”：确定性修复已通过下列回归，但短 Prompt 的稳定规划、真实多页章节视觉、完整六次独立 Fresh 重测及 Windows 验收仍未完成。

## 从真实六次测试定位的问题与局部修复

| 问题 | 实际修改 | 证据与限制 |
|---|---|---|
| 同一故事用不同 Decision ID 提前拆开 | 在原 Execution Brief 校验中加入源哈希绑定的相邻决策边界审阅；全章 QA 跨 Decision ID 检查 | 反例拒绝缺少依据的边界；自由文本审阅仍不能自动证明管理语义 |
| 候选只换外层 padding，不解决节点内部容量 | 现有浏览器修复函数实测节点/边标签换行，有限宽度转移；压紧冗余容器，不改字、字号和关系 | 通用三节点样例 190px → 94px；B1/B2 固定失败输入均恢复单页生成 |
| 相同布局重复算修复 | Capacity Attempt 增 layoutSignature、equivalentTo、effectiveRepair、objectRepairs | 可以区分有效实测修复和等价候选；不把四个名字当四种有效构图 |
| 原生 PPT 与浏览器换行不同 | VP 文本按浏览器行冻结，预留实测字形宽度余量，在同一测量矩形内编译 | B2 最后一个字换行导致的原生溢出消失；无自动缩字 |
| 模块内有数字就算该对象事实出现 | visibleFacts.targetId 绑定具体节点；DOM 和最终原生对象按节点检查 | 调换两个对象数字的反例失败；原生导出/导入专项通过。旧输入未声明 targetId 的事实仍需实际语义审阅 |
| QA 自填 PASS、忽略跨页割裂 | 每页必须记录实际视觉观察；全章标题链、相邻边界、容量引用独立于 Planner 分组 | 缺观察、缺全章记录、缺容量引用的反例失败；记录存在不等于审美自动通过 |
| 安装目录带历史实现和测试记录 | 运行包白名单只收当前执行合同；Windows 同步白名单；运行指纹一致 | package/source 指纹相同，历史报告与测试 fixtures 不进入运行包；这不是主机访问隔离 |
| 网络、共享节点、回流及 anchor/overlay 尚缺闭环 | 延续本轮之前已完成的现有 Scene/Canvas/Compiler 局部修改 | 10 个拓扑页面原生对象检查通过；未新增原语或业务模板 |

## B1/B2 故障复测

使用用户冻结测试的**原 source model、原 IR、原任务卡**，只更换候选代码。未覆盖测试产物。目的仅为定位后的编译/容量故障验证，不是 Raw Source → Planner Fresh Run。

| 输入 | 旧结果 | 本轮固定输入结果 | 构建耗时 | 实际视觉判断 |
|---|---|---|---:|---|
| B1 | 无 PPT，容量失败 | 1 页原生 PPT，严格正文容量门禁下再次通过 | 14.321 秒 | 仍有重复标签、主次不够清楚，不能宣称 executive accepted |
| B2 | 无 PPT，compact 溢出 | 1 页原生 PPT，技术候选通过 | 15.586 秒 | 可读但长主指标夹带说明，仍需 Planner 字段组织复测 |

两张原生渲染图均实际查看。以上耗时仅为构建，不包含本轮代码调试、Planner、视觉复核和人工等待；其余阶段未完整计时，不能报告为零。

最终检查补上了容量证据与通过状态的一致性：即使外层返回 PASS，实测正文越界/文字碰撞也必须拒绝。B1 初次复测的空容器边缘超出正文约10px，压紧现有容器后重新生成；不通过放宽门禁或降低字号解决。

## 可执行验收

- `npm test`：通过（包含来源、路由、布局、完整构建、六类原生图表及最终表格回归）。原生图表测试本身输出待语义/视觉审阅，不冒充 Windows 确认。
- `test:rc5-primitives`：通过，实测非等宽内部修复保留全文和关系。
- `test:rc5-capacity`：通过，36 行数据经过 22 次完整/续页候选测量，形成 3 页自然续页，所有行及条件保留。
- `test:rc5-topology`：通过，共享节点、分支、回流、自环、anchor/overlay 原生检查。
- `test:rc5-scenes`：通过，十个合成领域、26 次候选测量；不是十个真实章节。
- `design-intent.e2e`：通过，时间/依赖/并行硬要求及节点级最终事实绑定。
- `test:publication`：通过，模拟增删改排后的实际 PPT 页序作为 HTML 唯一来源；不是 PowerPoint 人工操作实测。
- `runtime-package`：通过，运行包指纹一致且历史资料排除。

## 未完成验收与下一步

1. A1/A2/B1/B2/C1/C2 六个原始会话已收集，但包含中断重试、历史资料访问、失败生成，不能记作六次合格 Fresh。新代码后的六次同模型、同源、同 Prompt 独立运行尚无证据。
2. R02–R05 对短 Prompt 自主理解的改进不能仅用预制 IR 证明，需要上述真实 Planner 重测。
3. 真实多页章节 Golden Benchmark 未完成；36 行合成表和十个单页领域不能替代。
4. 默认视觉质量并未全部达到接受标准，尤其长字段组织、冗余叙述、对象差异化及故事集中度。仅增加审阅门禁不能代替修好页面。
5. Windows PowerPoint 的实际打开、编辑、保存、重开、渲染仍无环境证据。
6. 完整端到端 Timing 不齐全；保留可观测数据及未知阶段，不拿构建秒数冒充制作总耗时。

本次没有新增 Agent、框架、服务、数据库、业务模板或原语类型。运行包脚本只是已有文件的白名单复制和指纹检查。未修改 HTML/Deck Skill，未覆盖用户已有 PPT。
